## 우리 감독기는 어떻게 판단하나

감독기는 0.05 s마다 MPC 출력을 검사합니다 (`08_carla_paired_run/av_stack/integration/supervised_lateral.py`).

1. **출력이 쓸 만한가**: 솔버 실패, NaN, 조향 범위 초과(최대각 *초과*만), 계산 시간 초과, 오래된 출력(시각 차이 0.1 s 초과, 번호가 늘지 않음). 하나라도 걸리면 그 주기에 바로 LQR로 넘어갑니다.
2. **경로를 잘 따라가나**: MPC가 보고한 횡오차가 1 m(방향 오차 0.6 rad)를 넘은 상태가 0.25 s 이어지면 넘어갑니다. 중간에 정상 샘플이 하나라도 나오면 타이머가 처음부터 다시 셉니다.

LQR로 넘어가면 MPC로 돌아오지 않습니다.

## 고장 7종

서로 다른 실패 원인(명시적 실패, 오래된 메시지, 시간 지연, 은밀한 값 오염, 점진적 오염, 급격한 이상, 감독기 타이머)을 하나씩 구분해서 시험합니다.
위험 고장(F-03~07)은 **CARLA 세 경로 모두에서 전환 실패·지연 또는 주행 성능 저하가 확인된 것**만 남겼습니다 (아래 검증 결과).
F-04·F-05·F-07은 같은 조향 오염에 시간 패턴(상수, 기울기, 켜고 끔)만 다르게 적용합니다.

| ID | 고장 | 뭐 하는 고장인지 | 구분 | 확인할 것 | 범위 | `--mpc-fault` |
|---|---|---|---|---|---|---|
| F-01 | 명시적 계산 실패 | MPC가 "답을 못 구했다"고 보고 | 대조군 | 실패 상태를 받으면 정상 전환하는가 | 지속 0.1–3 s | `solver_fail` |
| F-02 | 오래된 메시지 | 직전 메시지를 값·시각·번호까지 통째로 반복 | 대조군 | 출력 중단을 제때 감지하는가 | 지속 0.1–3 s | `stale` |
| F-03 | 출력 지연 | k틱 전에 계산한 명령을 현재 시각·번호로 내보냄 (처리 지연) | 위험: 시간 문제 | 늦은 명령 처리와 전환 지연 | 1, 2, 3, 4, 6틱 | `output_delay` |
| F-04 | 지속 bias | 조향값에 일정한 각도를 계속 더함 | 위험: 은밀한 값 오염 | 감지 누락과 전환 후 회복 | 0.02–0.10 rad | `bias` |
| F-05 | drift | 조향 오차가 시간이 갈수록 커짐 | 위험: 점진적 값 오염 | 악화 속도에 따른 감지·전환 지연 | 0.005–0.05 rad/s | `drift` |
| F-06 | 최대 조향 고정 | 조향을 정확히 최대각에 고정 (범위 검사 통과) | 위험: 급격한 이상 | 급격히 악화된 상태에서의 인계·회복 | 지속 0.1–1.0 s, 부호 ± | `saturate` |
| F-07 | 간헐·주기적 bias | bias를 간헐·주기적으로 켜고 끔 | 위험: 감독기 취약점 | 타이머 리셋으로 인한 전환 누락 | 0.05–0.15 rad, 켜짐 0.1–1.0 s, 꺼짐 0.05–1.0 s | `intermittent_bias` |

F-02는 "값만 고정하고 시각·번호는 갱신"하는 경우와 다른 시험입니다. 그 경우는 정상 메시지처럼 보여 확장 E-01로 둡니다.
F-03을 옛 시각·번호 그대로 늦게 보내면 시작 순간 번호가 줄어들어 번호 검사에 바로 걸립니다. 그래서 명령 내용만 늦추고 시각·번호는 현재 값을 씁니다.
기존 `delay`(75 ms sleep)는 계산 시간 초과로 즉시 전환되고, CARLA 동기 모드라 차량에는 영향이 없어 F-03과 다릅니다.

## 사용법

저장소 루트에서 (PyYAML 필요):

```
python -m engine.fault_catalog --check
python -m engine.fault_catalog --sample 5 --seed 0
python -m engine.fault_catalog --self-test
python -m engine.fault_args --self-test
```

`--sample`은 시나리오를 JSON 한 줄씩 출력합니다:

```json
{"fault_id": "F-05", "fault": "drift", "params": {"rate_rad_s": 0.040}, "timing": {"onset_event": "straight", "offset_s": -0.02}, "environment": {"max_speed_kmh": 36.8, "tire_friction_scale": 0.57}}
```

`--sample`은 무작위로 뽑으므로 비교용(무작위 기준선)과 테스트용입니다. 실제 파이프라인에서는 환경을 Nemotron A가, 고장 계획을 Nemotron B가 정합니다.

`engine/fault_args.to_cli(space, scenario, onset_s)`가 고른 계획을 `run_benchmark.py` 인자로 바꿉니다.
`onset_s`(주입 시각)는 호출하는 쪽이 경로에서 `onset_event` + `offset_s`를 찾아 넘깁니다.

```
['--mpc-fault', 'intermittent_bias', '--fault-start', '11.00', '--fault-duration', '500.00', '--fault-magnitude', '0.1107', '--fault-on', '0.790', '--fault-off', '0.711', '--max-speed', '16.9']
```
